# OpenClaw 2026.6.11 版本变更说明

发布时间：2026-06-28
适配教程版本：v2.2.0

> ⚠️ **Beta 版本**：v2026.6.11-beta.1 为测试版本，部分功能可能在正式版中调整。生产环境请谨慎使用。

---

## 📋 版本更新概要

v2026.6.11-beta.1 是一个重要的平台扩展版本，**100%向下兼容v2026.6.10所有配置**，无破坏性变更。本版本重点引入了 Slack Relay 模式、Mattermost 原生支持、Per-DM 模型覆盖等核心特性，同时在多个通道和工具链上进行了增强。

---

## ✨ 新功能介绍

### 1. Slack Relay 模式

✅ 全新的 Slack 集成方式，通过 Relay 中继层桥接 Slack 消息：

| 特性 | 说明 |
|------|------|
| Relay 模式 | 基于中继的消息桥接，替代传统 Webhook |
| 自动重连 | 断线后自动恢复连接 |
| 富文本支持 | 支持 Slack Block Kit 格式 |
| 线程支持 | 原生线程内回复 |
| 多频道监听 | 同时监听多个频道和私信 |

**配置示例**：
```json
{
  "channels": {
    "slack": {
      "enabled": true,
      "mode": "relay",
      "token": {
        "bot": "xoxb-你的Bot-Token",
        "signing": "你的Signing-Secret"
      },
      "relay": {
        "endpoint": "https://你的服务器:18789/slack/events",
        "retryPolicy": "exponential",
        "maxRetries": 5
      },
      "features": {
        "threads": true,
        "richText": true,
        "reactions": true
      }
    }
  }
}
```

> 📖 详细配置请参考 [Slack 对接教程](../integration/slack-integration.md)

### 2. Mattermost 原生 `/oc_queue` 命令

✅ Mattermost 通道新增原生斜杠命令支持：

| 特性 | 说明 |
|------|------|
| `/oc_queue` | 原生斜杠命令提交 AI 任务 |
| 命令自动完成 | 支持命令提示和自动补全 |
| 角色权限 | 支持按角色限制命令使用 |
| 队列管理 | 支持查看和清空任务队列 |

**使用示例**：
```
# 提交任务
/oc_queue 帮我分析这段代码

# 查看队列状态
/oc_queue --status

# 指定模型
/oc_queue --model deepseek-r1 解释量子计算
```

**配置示例**：
```json
{
  "channels": {
    "mattermost": {
      "enabled": true,
      "server": "https://mattermost.example.com",
      "token": "你的Bot-Token",
      "commands": {
        "oc_queue": {
          "enabled": true,
          "allowedRoles": ["system_admin", "team_admin", "team_user"]
        }
      }
    }
  }
}
```

> 📖 详细配置请参考 [Mattermost 对接教程](../integration/mattermost-integration.md)

### 3. Per-DM 模型覆盖

✅ 为不同的私信对话设置独立的 AI 模型：

| 特性 | 说明 |
|------|------|
| 按对话配置 | 每个 DM 对话可独立设置模型 |
| 全局回退 | 未配置的对话使用全局默认模型 |
| 动态切换 | 支持运行时通过命令切换 |
| 多通道支持 | 所有支持 DM 的通道均可使用 |

**配置示例**：
```json
{
  "models": {
    "default": "gpt-4o",
    "dmModelOverrides": {
      "telegram:user:123456789": "claude-sonnet-4",
      "telegram:user:987654321": "deepseek-r1",
      "feishu:user:ou_abc123": "gpt-4o-mini"
    }
  }
}
```

> 📖 详细配置请参考 [Per-DM 模型覆盖配置](../configuration/per-dm-model.md)

### 4. 更安全的插件分发

✅ 插件分发安全机制全面增强：

| 特性 | 说明 |
|------|------|
| 签名验证 | 插件安装前验证数字签名 |
| 哈希校验 | 下载完成后校验文件哈希 |
| 来源白名单 | 只允许从白名单来源安装插件 |
| 沙箱运行 | 新安装插件默认在沙箱中运行 |

**配置示例**：
```json
{
  "plugins": {
    "security": {
      "signatureVerification": true,
      "hashCheck": true,
      "trustedSources": [
        "registry.openclaw.ai",
        "github.com/openclaw"
      ],
      "sandboxNewPlugins": true
    }
  }
}
```

### 5. Android 设置面板

✅ Android 客户端新增设置面板：

| 功能 | 说明 |
|------|------|
| 快速配置 | 在手机端快速修改常用配置 |
| 模型切换 | 快速切换默认模型 |
| 通道管理 | 启用/禁用消息通道 |
| 状态监控 | 实时查看 gateway 状态 |

### 6. Codex 部分增量更新

✅ Codex 模式支持部分增量更新（Partial Deltas）：

| 特性 | 说明 |
|------|------|
| 增量输出 | 只发送变化的部分，减少带宽 |
| 实时渲染 | 代码变更实时渲染 |
| 冲突处理 | 自动处理增量更新冲突 |
| 回滚支持 | 支持回滚到任意增量版本 |

**配置示例**：
```json
{
  "codex": {
    "partialDeltas": {
      "enabled": true,
      "minDeltaSize": 100,
      "compressionLevel": 1
    }
  }
}
```

### 7. Telegram 进度渲染

✅ Telegram 通道长任务进度实时渲染增强：

| 特性 | 说明 |
|------|------|
| 进度条 | 长任务显示进度条 |
| 状态消息 | 实时更新处理状态 |
| 预估时间 | 显示预计完成时间 |
| 取消支持 | 支持用户取消进行中的任务 |

### 8. WhatsApp 持久回复目标

✅ WhatsApp 通道支持持久回复目标（Durable Reply Targets）：

| 特性 | 说明 |
|------|------|
| 持久目标 | 回复目标消息 ID 持久化存储 |
| 断线恢复 | 断线重连后仍能正确回复 |
| 多设备 | 多设备登录时回复一致性 |
| 消息排序 | 保证消息顺序正确 |

**配置示例**：
```json
{
  "channels": {
    "whatsapp": {
      "durableReplyTargets": {
        "enabled": true,
        "persistInterval": 5000,
        "maxAge": 86400000
      }
    }
  }
}
```

### 9. `--message-file` CLI 选项

✅ 新增命令行消息文件选项：

| 特性 | 说明 |
|------|------|
| 文件输入 | 从文件读取消息内容 |
| 批量处理 | 支持批量消息处理 |
| 格式支持 | 支持纯文本和 Markdown 格式 |
| 编码支持 | 支持 UTF-8 和 UTF-16 编码 |

**使用示例**：
```bash
# 从文件发送消息
openclaw send --message-file ./prompt.txt --channel telegram

# 批量处理
openclaw batch --message-file ./tasks.txt --output ./results/
```

### 10. RAFT CLI 唤醒桥接

✅ RAFT CLI 新增唤醒桥接功能：

| 特性 | 说明 |
|------|------|
| 远程唤醒 | 通过 CLI 远程唤醒休眠的 gateway |
| 事件触发 | 支持事件触发唤醒 |
| 低功耗 | 唤醒后自动进入低功耗监听 |
| 安全认证 | 唤醒请求需安全认证 |

**使用示例**：
```bash
# 唤醒 gateway
openclaw raft wake

# 检查唤醒状态
openclaw raft status

# 配置唤醒监听
openclaw raft listen --port 18790
```

**配置示例**：
```json
{
  "raft": {
    "wakeBridge": {
      "enabled": true,
      "listenPort": 18790,
      "authToken": "你的唤醒Token",
      "idleTimeout": 300000
    }
  }
}
```

## 🚀 升级步骤

### 常规升级

```bash
# 1. 停止gateway服务
openclaw gateway stop

# 2. 升级到 beta 版本
openclaw update --channel beta

# 3. 自动修复配置（可选，推荐执行）
openclaw doctor --fix

# 4. 启动gateway服务
openclaw gateway start

# 5. 验证版本
openclaw version  # 输出应为v2026.6.11-beta.1
```

### Docker部署升级

```bash
# 1. 拉取 beta 镜像
docker pull openclaw/openclaw:beta

# 2. 停止当前容器
docker stop openclaw

# 3. 启动新容器
docker run -d \
  --name openclaw \
  -v ~/.openclaw:/root/.openclaw \
  -p 18789:18789 \
  openclaw/openclaw:beta

# 4. 验证版本
docker exec openclaw openclaw version
```

## ⚠️ 注意事项

1. **Beta 版本**：本版本为测试版本，生产环境建议等待正式版发布
2. **Slack Relay**：需要公网可访问的回调地址
3. **Mattermost 命令**：需要在 Mattermost 中手动注册斜杠命令
4. **插件签名验证**：启用后第三方未签名插件将无法安装
5. **RAFT 唤醒桥接**：需要额外开放端口
