# Fast Talks 自动快速模式

> 使用 Fast Talks 功能加速简短对话，在快速模式和正常模式之间智能切换

**版本要求**：OpenClaw v2026.6.10 或更高版本

---

## 📋 前置要求

- OpenClaw v2026.6.10 或更高版本
- 已完成消息平台配置

---

## 功能说明

Fast Talks 是 OpenClaw v2026.6.10 引入的自动快速模式功能。在快速模式下，AI 使用更轻量的处理流程来响应简短的对话轮次，显著降低延迟和 Token 消耗。当检测到需要更复杂处理的长任务时，系统会自动回退到正常模式。

### 核心特性

- ⚡ **低延迟**：简短对话在快速模式下响应更快
- 🔄 **智能切换**：自动在快速模式和正常模式之间切换
- 📊 **节省 Token**：快速模式消耗更少的 Token
- 💾 **状态保持**：从快速模式回到正常模式时，已有的可见状态会被保留
- 🛡️ **有界回退**：长任务会可靠地回退到正常模式

## 基本命令

### 1.1 启用自动模式

```
/fast auto
```

启用自动模式后，系统会根据对话长度自动决定使用快速模式还是正常模式：

```
用户: /fast auto
AI: ✅ Fast Talks 自动模式已启用。简短对话将使用快速模式，长任务将自动回退到正常模式。
```

### 1.2 手动开启快速模式

```
/fast on
```

强制开启快速模式，所有对话都使用快速模式处理：

```
用户: /fast on
AI: ⚡ 快速模式已开启。
```

### 1.3 关闭快速模式

```
/fast off
```

关闭快速模式，回到正常模式：

```
用户: /fast off
AI: ✅ 已切换回正常模式。
```

### 1.4 查看当前状态

```
/fast status
```

```
用户: /fast status
AI: 📊 Fast Talks 状态：
模式: auto
当前处理模式: fast
本次快速轮次: 5
本次正常轮次: 1
```

## 使用示例

### 2.1 日常简短对话

在自动模式下，简短对话会自动使用快速模式：

```
用户: /fast auto
AI: ✅ Fast Talks 自动模式已启用。

用户: 今天天气怎么样？
AI: 请问你在哪个城市？

用户: 北京
AI: 北京今天晴，最高温度 32°C，注意防晒。
```

以上对话在快速模式下完成，响应更快、消耗更少。

### 2.2 自动回退到正常模式

当对话变长或任务复杂时，系统会自动回退：

```
用户: /fast auto
AI: ✅ Fast Talks 自动模式已启用。

用户: 简单说下什么是 Docker
AI: Docker 是一个容器化平台，可以将应用及其依赖打包到一个轻量的容器中运行。

用户: 帮我写一个完整的 Docker Compose 文件，包含 Nginx、PostgreSQL、Redis，要求支持热重载、健康检查、日志收集，并且要有详细的注释说明每个配置项的作用，还要附上部署文档
AI: [自动切换到正常模式] 好的，这是一个复杂的配置任务，我来详细为你编写...
```

### 2.3 手动控制模式

```
用户: /fast on
AI: ⚡ 快速模式已开启。

用户: 写一个 Python hello world
AI: print("Hello, World!")

用户: /fast off
AI: ✅ 已切换回正常模式。
```

## 配置说明

编辑 `~/.openclaw/config.json` 进行 Fast Talks 配置：

```json
{
  "fast_talks": {
    "enabled": true,
    "default_mode": "auto",
    "auto_threshold": 500,
    "max_fast_tokens": 1024,
    "preserve_state": true,
    "fallback_grace_period": 3000,
    "delivery": "incremental"
  }
}
```

### 配置项说明

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `enabled` | 是否启用 Fast Talks 功能 | `true` |
| `default_mode` | 默认模式（`auto` / `on` / `off`） | `auto` |
| `auto_threshold` | 自动模式下触发回退的 Token 阈值 | `500` |
| `max_fast_tokens` | 快速模式下最大生成 Token 数 | `1024` |
| `preserve_state` | 回退到正常模式时是否保留可见状态 | `true` |
| `fallback_grace_period` | 回退的宽限期（毫秒） | `3000` |
| `delivery` | 交付方式（`incremental` / `batch`） | `incremental` |

## 何时使用快速模式 vs 正常模式

### 3.1 适合快速模式的场景

| 场景 | 示例 |
|------|------|
| 简单问答 | "什么是 HTTP？" |
| 短句翻译 | "把这句话翻译成英文" |
| 快速确认 | "这样写对吗？" |
| 闲聊 | "今天天气不错" |
| 简单计算 | "123 * 456 等于多少" |
| 状态查询 | "上次部署成功了吗？" |

### 3.2 需要正常模式的场景

| 场景 | 示例 |
|------|------|
| 复杂代码生成 | 编写完整的项目模块 |
| 长文写作 | 撰写技术文档、博客文章 |
| 深度分析 | 代码审查、架构设计 |
| 多步推理 | 调试复杂问题 |
| 执行工具 | 运行 shell 命令、文件操作 |
| 大量上下文 | 处理长代码片段或文件 |

## 行为说明

### 4.1 状态保持

快速模式返回正常模式时，已有的可见状态会被保留：

```
用户: /fast auto
用户: 帮我写一个 Python 函数
AI: [快速模式] def hello(): print("Hello")
用户: 加上异常处理和日志
AI: [自动切换到正常模式，保留上面的函数代码]
```

这意味着：
- 快速模式下的对话历史不会丢失
- 已生成的代码、表格、列表等保持可见
- 正常模式在已有基础上继续工作

### 4.2 有界回退

当自动模式检测到需要回退时：

1. **检测**：分析用户输入的长度和复杂度
2. **宽限期**：在 `fallback_grace_period` 时间内完成切换
3. **切换**：从快速模式平滑过渡到正常模式
4. **通知**：向用户显示模式切换提示（可配置）

### 4.3 交付行为

| 交付方式 | 说明 |
|----------|------|
| `incremental` | 增量交付，逐段发送响应，适合即时反馈 |
| `batch` | 批量交付，等待完整响应后一次性发送，适合长内容 |

快速模式下默认使用 `incremental` 以获得最佳响应速度。

## 常见问题

### Q: 快速模式的回答质量会下降吗？

快速模式针对简短对话进行了优化，回答质量对于简单问题不会有明显下降。对于复杂问题，系统会自动回退到正常模式，确保回答质量。

### Q: 快速模式和正常模式的 Token 消耗差多少？

快速模式的 Token 消耗通常比正常模式低 30%~50%，具体取决于对话内容和模型。

### Q: 如何强制所有对话都使用快速模式？

使用 `/fast on` 命令强制开启快速模式。但请注意，复杂任务可能会产生不完整或质量较低的回答。

### Q: 自动模式的判断依据是什么？

自动模式根据以下因素判断：
- 用户输入的长度（字符数和 Token 数）
- 是否包含代码、多行文本等复杂内容
- 是否涉及工具调用或多步推理
- 阈值设置（`auto_threshold`）

### Q: 模式切换时会中断当前对话吗？

**不会**。模式切换是平滑的，当前对话不会被中断。切换会在下一轮对话生效。

### Q: `preserve_state` 关闭后会怎样？

关闭后，从快速模式回退到正常模式时，快速模式下的对话上下文可能不会完整保留。建议保持默认开启状态。

---

## 最佳实践

1. **使用自动模式**：推荐使用 `/fast auto` 而非手动切换，让系统智能决定
2. **合理设置阈值**：根据使用习惯调整 `auto_threshold`，频繁复杂任务可适当调高
3. **保持状态保持开启**：`preserve_state` 应保持 `true`，避免对话中断
4. **增量交付优先**：日常使用推荐 `incremental` 交付方式，获得更好的交互体验
5. **关注状态**：使用 `/fast status` 定期检查当前模式，确保符合预期
