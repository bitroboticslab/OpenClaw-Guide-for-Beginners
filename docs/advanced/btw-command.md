# /btw 旁白命令使用说明

> 使用 /btw 命令为 AI 添加旁白、注释和上下文信息，不消耗额外 Token

## 📋 前置要求

- OpenClaw v2.0.0 或更高版本
- 已完成消息平台配置

---

## 功能说明

`/btw`（by the way）是 OpenClaw v2.0.0 新增的旁白命令，用于向 AI 传递额外的上下文信息、注释或提示，而不会打断正常的对话流程。

### 核心特性

- 📝 **添加旁白**：为 AI 提供额外背景信息
- 🚫 **不消耗 Token**：旁白内容不计入 Token 消耗
- 🎭 **角色分离**：旁白内容与用户消息分离
- 📌 **上下文注入**：在不改变对话的情况下注入信息

---

## 基本用法

### 1.1 简单旁白

```
用户: 帮我写一封邮件
/btw 用户是产品经理，收件人是技术团队负责人
AI: 好的，我来帮你写一封面向技术团队的邮件...
```

### 1.2 多行旁白

```
用户: 分析这段代码
/btw
这是一个 Python 项目
使用 Django 框架
代码风格需要遵循 PEP 8
/btw
AI: 我来按照 PEP 8 标准分析这段 Django 代码...
```

### 1.3 行内旁白

```
用户: 帮我翻译这段话 btw 这是给日本客户的邮件，需要正式用语
AI: 好的，我会使用正式的日语表达来翻译...
```

## 使用示例

### 2.1 设置对话场景

```
用户: 你好，请帮我写一个函数
/btw 用户是初学者，需要用简单易懂的方式解释
AI: 好的！我来用简单的方式帮你写一个函数，并解释每一步...
```

### 2.2 指定输出格式

```
用户: 列出 Python 的数据类型
/btw 请用表格形式展示，包含类型名称、示例和说明
AI: 好的，以下是 Python 数据类型表格：

| 类型 | 示例 | 说明 |
|------|------|------|
| int | 42 | 整数 |
| str | "hello" | 字符串 |
| ... | ... | ... |
```

### 2.3 提供背景知识

```
用户: 这个报错怎么解决？
/btw 用户使用的是 Python 3.11，操作系统是 Ubuntu 22.04
AI: 根据 Python 3.11 和 Ubuntu 22.04 的环境，这个报错的解决方法是...
```

### 2.4 调整回复风格

```
用户: 解释一下什么是 Docker
/btw 请用通俗易懂的语言，避免技术术语，适合非技术人员理解
AI: 想象一下，你有一个魔法箱子...
```

### 2.5 添加约束条件

```
用户: 帮我设计一个数据库表
/btw
数据库使用 MySQL 8.0
需要支持软删除
必须包含 created_at 和 updated_at 字段
主键使用 UUID
/btw
AI: 好的，我来设计一个符合要求的 MySQL 表...
```

## 场景说明

### 3.1 编程辅助场景

**场景**：需要 AI 按照特定编码规范生成代码

```
用户: 写一个用户注册函数
/btw
语言：Python 3.11
框架：FastAPI
ORM：SQLAlchemy 2.0
需要参数验证（Pydantic）
返回 JSON 格式响应
/btw
```

**效果**：AI 会生成符合所有约束的 FastAPI 注册函数。

### 3.2 文档写作场景

**场景**：需要 AI 按照特定风格撰写文档

```
用户: 写一段产品介绍
/btw
产品：OpenClaw
目标用户：开发者
风格：专业但不失亲和力
长度：200字左右
需要包含核心功能和优势
/btw
```

### 3.3 学习辅导场景

**场景**：调整 AI 的教学方式

```
用户: 解释一下递归
/btw
用户是计算机科学大一学生
之前没接触过递归概念
需要用生活中的例子来解释
最后给出一个简单的代码示例
/btw
```

### 3.4 翻译场景

**场景**：指定翻译的语境和风格

```
用户: 把这句话翻译成英文：这个功能还在开发中
/btw
语境：技术文档
风格：正式
不需要直译，需要符合英文技术文档的表达习惯
/btw
```

**效果**：`This feature is currently under development.`

### 3.5 调试场景

**场景**：提供调试上下文

```
用户: 这段代码为什么报错？
/btw
已尝试的解决方案：
1. 重启服务 - 无效
2. 清除缓存 - 无效
3. 检查依赖版本 - 都是最新的
错误只在生产环境出现，本地开发正常
/btw
```

## 高级用法

### 4.1 持久旁白

设置一个旁白，在整个会话中持续生效：

```
/btw! 本次会话中，请始终使用中文回复，并在代码注释中使用英文
```

> 使用 `!` 后缀表示持久旁白，会一直生效直到会话结束或被清除。

### 4.2 清除持久旁白

```
/btw clear
```

### 4.3 查看当前旁白

```
/btw show
```

输出：

```
📌 当前活跃旁白：
━━━━━━━━━━━━━━━━━━━━
[持久] 请始终使用中文回复，代码注释使用英文
━━━━━━━━━━━━━━━━━━━━
```

### 4.4 旁白与系统提示词的区别

| 特性 | 旁白 (/btw) | 系统提示词 |
|------|------------|-----------|
| Token 消耗 | ❌ 不消耗 | ✅ 消耗 |
| 作用范围 | 当前会话 | 全局 |
| 优先级 | 中 | 高 |
| 可修改性 | 随时修改 | 需要重新配置 |
| 可见性 | 用户可见 | 通常隐藏 |

## 完整配置

### 启用/禁用旁白功能

编辑 `~/.openclaw/config.json`：

```json
{
  "commands": {
    "btw": {
      "enabled": true,
      "prefix": "/btw",
      "inline_prefix": "btw",
      "persistent_suffix": "!",
      "max_length": 2000,
      "inject_position": "system",
      "token_counting": false
    }
  }
}
```

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `enabled` | 是否启用旁白功能 | `true` |
| `prefix` | 命令前缀 | `/btw` |
| `inline_prefix` | 行内旁白前缀 | `btw` |
| `persistent_suffix` | 持久旁白后缀 | `!` |
| `max_length` | 单条旁白最大长度 | `2000` |
| `inject_position` | 注入位置（system/user） | `system` |
| `token_counting` | 是否计入 Token | `false` |

## 常见问题

### Q: 旁白内容会被 AI 看到吗？

**会**。旁白内容会作为上下文注入到 AI 的输入中，但不会显示为用户消息。

### Q: 旁白会影响 Token 消耗吗？

**默认不会**。`token_counting` 默认为 `false`，旁白内容不计入 Token 消耗。

### Q: 可以同时使用多个旁白吗？

**可以**。多个旁白会按顺序叠加注入。

### Q: 旁白和 `/system` 命令有什么区别？

- `/btw`：临时上下文，不消耗 Token，适合一次性提示
- `/system`：系统级指令，消耗 Token，适合长期规则

### Q: 行内旁白的格式是什么？

```
用户消息 btw 旁白内容
```

或

```
用户消息 btw: 旁白内容
```

## 最佳实践

1. **简洁明了**：旁白应简短，避免过长的上下文
2. **关键信息优先**：只提供对当前任务最重要的信息
3. **使用持久旁白**：对于会话级别的约束，使用 `!` 后缀
4. **合理分组**：多条相关约束放在同一个 `/btw` 块中
5. **及时清除**：不再需要的持久旁白及时清除
