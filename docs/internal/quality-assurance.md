# 质量保障体系

本文档定义OpenClaw Guide项目的质量保障标准、测试流程和验证矩阵。

---

## 🎯 质量目标

### 核心指标

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 链接有效率 | 100% | 自动化检查 |
| 命令正确率 | 100% | 语法检查+实际测试 |
| 版本一致性 | 100% | 自动化检查 |
| 术语统一率 | 100% | 自动化检查 |
| 用户满意度 | >90% | Issue反馈分析 |

### 质量原则

1. **准确性第一**: 所有内容必须100%准确
2. **新手友好**: 步骤详细，无跳步
3. **一致性**: 格式、术语、风格统一
4. **时效性**: 内容与最新版本同步

---

## 📋 测试验证矩阵

### 测试类型

| 测试类型 | 验证内容 | 验证方式 | 执行时机 | 负责人 |
|----------|----------|----------|----------|--------|
| **链接验证** | 所有内部/外部链接可访问 | markdown-link-check | 每次提交 | CI |
| **格式检查** | Markdown规范、标题层级 | markdownlint | 每次提交 | CI |
| **命令验证** | 所有bash命令语法正确 | bash -n | 每次提交 | CI |
| **版本一致性** | 版本号全文统一 | 自定义脚本 | 每次提交 | CI |
| **术语一致性** | 术语使用统一 | 自定义词典检查 | 每次提交 | CI |
| **功能测试** | 关键功能实际可用 | 手动+自动化 | 版本发布前 | 维护者 |
| **升级测试** | 升级流程完整可行 | 实际环境测试 | 版本发布前 | 维护者 |
| **兼容性测试** | 多平台兼容性 | 多环境测试 | 版本发布前 | 维护者 |

### 详细测试项

#### 1. 链接验证

**测试范围**:
- 内部文档链接
- 外部参考链接
- 邀证链接（作者链接）

**测试工具**:
```bash
# 安装
npm install -g markdown-link-check

# 运行
find docs -name "*.md" -exec markdown-link-check {} \;
```

**配置文件**: `.github/link-check-config.json`

**通过标准**:
- 所有内部链接有效
- 外部链接可访问率 > 95%
- 作者链接100%有效

#### 2. Markdown格式检查

**检查项**:
- 标题层级（不跳级）
- 代码块语言标注
- 列表格式一致
- 表格格式规范

**测试工具**:
```bash
# 安装
npm install -g markdownlint-cli

# 运行
markdownlint docs/**/*.md README.md
```

**配置文件**: `.github/markdownlint.json`

**通过标准**:
- 无格式错误
- 警告数 < 10

#### 3. 命令语法验证

**测试范围**:
- 所有bash代码块
- 安装脚本
- 配置命令

**测试工具**:
```bash
# 提取bash代码块
sed -n '/^```bash/,/^```$/p' file.md | grep -v '```' > /tmp/test.sh

# 语法检查
bash -n /tmp/test.sh
```

**通过标准**:
- 所有bash命令语法正确
- 无语法错误

#### 4. 版本一致性检查

**检查项**:
- README版本徽章
- CHANGELOG版本记录
- 文档内版本引用

**测试工具**:
```bash
# 检查README版本
grep -oP 'v\d+\.\d+\.\d+' README.md | head -1

# 检查CHANGELOG版本
grep -oP '## \[\K\d+\.\d+\.\d+' CHANGELOG.md | head -1
```

**通过标准**:
- 版本号全文一致
- README与CHANGELOG版本匹配

#### 5. 术语一致性检查

**检查项**:
- OpenClaw拼写（首字母大写）
- 专业术语使用
- 平台名称规范

**测试工具**:
```bash
# 检查OpenClaw拼写
grep -r "openclaw" docs/ --include="*.md" | grep -v "openclaw.ai"
grep -r "Openclaw" docs/ --include="*.md"
```

**通过标准**:
- 术语使用100%一致
- 无拼写错误

#### 6. 功能测试

**测试范围**:
- 安装流程
- 配置流程
- 平台对接流程

**测试方式**:
- 实际环境测试
- 虚拟机测试
- Docker容器测试

**测试环境**:
- Ubuntu 22.04/24.04
- macOS 14.x
- Windows 11 + WSL2

**通过标准**:
- 所有流程可顺利完成
- 无阻塞性错误

#### 7. 升级测试

**测试范围**:
- 版本升级流程
- 配置迁移
- 数据兼容性

**测试方式**:
- 从旧版本升级到新版本
- 验证配置完整性
- 验证功能正常

**通过标准**:
- 升级流程顺利完成
- 配置无丢失
- 功能正常

#### 8. 兼容性测试

**测试范围**:
- 不同Node.js版本
- 不同操作系统
- 不同浏览器（文档阅读）

**测试环境**:
- Node.js 20 LTS / 22 LTS / 24 LTS
- Ubuntu / macOS / Windows
- Chrome / Firefox / Safari

**通过标准**:
- 所有环境兼容
- 无环境特定错误

## 🔄 测试流程

### 开发阶段测试

```
开发分支 → 本地测试 → 提交PR → CI测试 → 人工审核 → 合并
    ↓           ↓           ↓           ↓           ↓
  代码开发    本地验证    自动触发    自动运行    人工确认
```

### 版本发布测试

```
功能完成 → 完整测试 → 修复问题 → 最终验证 → 发布
    ↓           ↓           ↓           ↓           ↓
  内容开发    全量测试    问题修复    确认通过    打tag发布
```
